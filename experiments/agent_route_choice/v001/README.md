## 目的与范围

回答“找到这个点之后，用 Agent 能不能找到更对的路线”。本版已知 Crossing，且已知先前有一次走错经历；验证模型能否将错误经历对应到某条支路，并结合任务选择正确道路。不评估 Crossing 检测能力、不评估自主触发纠错、不执行所选动作，也不评估最终导航成功率。

用户已授权两组各十条：GLM使用十个独立进程，本地模型改为Qwen3-VL-32B-Instruct；验证两组有效回答后停止人工持续跟踪，由后台完成。此前27B准备版本保留，不启动该旧配置。

## 方法与提示词

当前为第2稿（2026-11-06）：两次调用的 prompt 和描述输出均使用英文，中文文件只供用户审阅。第一稿已冻结于 preparation_20261106_02，不覆盖。第一调用开头采用此前 v003/v005 的 Crossing 定义：同一位置、除来路外至少两个可通行且通向不同空间的选择；两条不同走廊或两个同类房间也可构成不同去向。局部开口、侧向通道一角、墙后延伸地面等具体线索足以合理推断时计为支路，不因视野受限而直接排除。来路可额外记录用于识错，但不计入定义所需的两个后续选择。

1. 第一调用输入存档处 RGB、此前的视觉上下文和动作命令。独立列出 B1/B2 等支路、相对当前朝向的方向、地标、可能通往区域、是否来路和图像证据。此调用不输入任务指令或后来走错的经历。
2. 第二调用新建 system+user 请求，显式给出该模型第一调用的实际清单、任务指令、同一存档上下文及后来走错的 RGB/动作。识别错误支路，给出简短证据和任务偏差，排除该支路，选出有任务正向支持的另一支路。

两次没有隐式对话历史。第二调用不新增支路、不重新盘点来修补第一调用；如果遗漏正确路线，允许报告证据不足。每个模型仅消费自己的第一调用输出，不传入另一个模型的回答。所有方向锚定复位画面，不能按错误片段末帧朝向回答。动作命令仅表示发出的动作，不能保证无碰撞地移动成功。

## 离线输入

统一使用旧 pilot10 原顺序的十条任务，在原 seed2 无干预复现录像中均有已复核的错误片段。后来 checkpoint_action10 运行只有七条有效物理恢复配对，且另三条有未触发/技术失败；本轮不拼接不同运行来补齐十条。

本版“复位”是离线虚拟复位：回到原录像中已有 `review.decision_frame` 的 RGB 与当时朝向。它是给定 Crossing 的历史决策位置，不是路口中心坐标，也不是本次执行了仿真姿态恢复。保留该帧与标定点的真实距离，不改变位置以对齐参考路线。第六条距原 C 约 0.95 m，超出 Crossing 检测旧评分的 0.7 m 访问半径；本轮依据既有决策标注，不冒充满足旧几何访问判据。

从该时刻之前最近最多 16 个真实观测均匀选 4 张，含末张存档画面。错误片段从存档之后到原标注 `highlight_end_frame`，均匀选最多 4 张，含两端；终止或复用旧 RGB 的帧排除。第二调用合计最多 8 图。第一调用有此前最多 32 条动作；第二调用追加存档到错误片段末帧之前的完整动作命令。没有提供每个观测之后尚未执行的动作。

只裁取原 960×640 录像左上角 640×480 纯 RGB，绝不包含地图、坐标、结果或底部任务字幕。任务指令在第二调用单独提供。模型输入和评分标签分成不同文件；构造请求时只允许固定输入字段，拒绝额外参考路径/人工结论字段。

这批是已经看过并复核过的案例，不是新的独立盲测；历史 expected/actual 是已有地图＋RGB辅助复核，不称独立人工金标准。有限视角可能不足，原动作发生前已局部转向，均应按实际输入解释。两图/多图历史不等于新采集的全景扫描。

## 模型与运行

GLM 默认沿用已经跑通的 `glm-5.3-flash`、low 思考；本地使用现存 `Resource_Peng/models/Qwen3-VL-32B-Instruct/`，14个分片约66.7GB，模型文件config架构为 `Qwen3VLForConditionalGeneration`，不重新下载。Qwen关闭思考，BF16双卡TP=2、单并发、32K上下文、最多 8 图，复用 `.runtime/crossing_vllm27`。两者共用 prompt 和图像；模型及推理设置不同，不能将差异归因于某个单一设置。

每组十条×两次逻辑调用=20次，两组合计40次。GLM 初次最多3次网络尝试均遇HTTP429，恢复批次调整为最多8次、30–120秒加抖动退避；Qwen最多2次，固定请求重试；不自动加大输出预算、不做语义修复或第三轮推理。格式无效时保留实际回答，该样本失败，继续其他样本。GLM十个样本各一个独立进程，每个进程内部顺序执行两次调用；一条失败不停止其他条。Qwen单请求顺序处理十条，两模型组并行。

运行入口默认为 dry-run，只有显式 `--execute` 才会请求模型。没有启动指令时不得执行该参数。密钥通过 getpass 或 stdin 进入运行进程内存，不写配置、命令行、日志或子进程环境。Qwen 入口在实际运行时检查所有卡并对选定卡做两次空卡/显存检查、核验计算进程和主存，拒绝抢占；退出、失败或取消后清理自己创建且核验身份的服务进程，并记录显存快照。

## 评分

自动检查只负责结构、引用、支路编号、方向一致性及排除规则。语义评分在输出产生后，用冻结的正确/错误路线描述和真实图像，将每个模型的 B 编号对应为 `expected_route / wrong_route / other / unclear`；需记录复核者、证据图像和理由，评分表绑定实际回答哈希。地图文字里的“左/右/上/下”可能是地图方向，不能与模型的相机相对方向直接做字符串比较。

主指标为正确选择任务支路的条数/固定10条。另报清单是否包含正确及错误路线、错误支路识别、错误原因是否有证据、识错且选对的联合比例、主动给出选择的覆盖率。请求失败和弃答计入全十条分母；尚未复核不能默认为错误，更不能自动算成功。全部已有回答复核之前，不输出完整比例。

同一样本两模型的结果按行对照。最终 SR 不在本轮指标中，不为本轮计算 Crossing 检测 F1。
