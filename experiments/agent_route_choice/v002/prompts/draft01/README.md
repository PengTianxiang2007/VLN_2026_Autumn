## 输入与传递约定

1. `crossing_panorama`：使用 `outputs/agent_route_choice/v002/capture_20261106_04/` 的八张原始RGB；V0–V7相对V0的朝向依次为0°、45°、90°、135°、180°、225°、270°、315°，正向向左。V是视图编号，不是B支路编号。只传相对角度及图像，不传地图、坐标、Oracle正确路线或几何标注的支路数。
2. `approach_history`：复用原seed2录像的四张存档前/存档时RGB和此前动作，保留原F编号；有些历史位置与标定点有偏移、朝向未恢复，不按像素精确对齐。第一轮不提供任务指令，也不提供之后走错的图像。
3. 第一轮计划输入8张全景+4张历史，共12张。来路保留在完整清单中，只从定义中的后续选择数排除；明确识别需要到达历史与全景共同支持，不能把V4直接当作来路。
4. 第二轮新建独立请求，显式提供同一模型第一轮实际完整JSON作为 `branch_inventory`，含全部B编号、方向、入口、视图证据及来路判断，不仅传支路数或摘要。再提供任务指令、同样八张全景和四张历史，以及原四张错误尝试图像与动作，计划共16张。
5. 任何第二轮编号必须存在于第一轮清单。排除集合等于已知错误支路和已知来路的去重并集，两者允许相同。选择需要二者均已识别及正向任务证据；不能选已排除路线。第一轮未知的来路可在第二轮确定；如果与第一轮明确标识冲突则弃答，不悄悄改写清单。
6. 第一轮输出`panorama_view_ids`及证据字段，第二轮输出`selected_panorama_view_ids`，方便之后可视化直接显示“有哪些支路／哪条为来路／哪条走错／选哪条／依据哪几张全景图”。
