# 节点去重 v001

直接消费此前已经采样得到的节点。使用第 1、2、3、4、7 条轨迹的全部 42 个原始采样点；不应用节点消除结果，不重新采样，不模拟逐帧到达或人为等待。

五个独立进程各处理一个 case。同一 case 内按候选帧号顺序逐个取节点 B，与当前最后一个已建立节点 A 比较。先等本次模型返回，再更新节点状态，然后才取下一个候选。第一节点直接建立；步数差超过 8 时直接建立 B，不调用模型。步数按轨迹动作帧号计算，包含等于 8。

步数差不超过 8 时，模型分别接收 A、B 周围各五帧（−2、−1、0、+1、+2）。初始缺失帧明确标记，不补帧。每组证据不晚于该采样点原有确认时刻。没有输入地图、任务指令、未来候选或整段轨迹。

模型明确确认两组实际物理分支完整对应、双方均无独有分支时，删除旧 A、建立新 B。不同、不确定、调用错误或无效输出都保留 A 并建立 B。下次仍与刚建立的 B 比较。原始节点记录不修改；最终保留集合只是原始节点的子集，帧号、编号不变。连续替换可以形成 A→B→C 的链；8 步限制逐次比较，不对整条链的累计跨度另设限制。

网页的“节点去重”默认为关闭，位于地图标题旁和下方独立控制区。勾选后波形、俯视地图同步使用完整去重结果，不随进度条隐藏节点。取消勾选恢复原采样点。右侧观测提示当前保留节点或被替换节点；展开审核可看 A/B 图像、理由、对应分支、建立顺序和实际提示词。

缓存结果仅在同一 case、同一采样参数、同一有序候选集和图像证据匹配时生效。若节点消除或参数变化导致候选集改变，保留当前节点并提示尚无适用的去重结果，避免套用错误的“上一个节点”。浏览器只读本地结果，不调用 API。

文件：`manifest.json` 保存固定输入；`prompt_zh.txt` 为实际中文提示词；`cases/Cxx/events.jsonl` 为顺序事件；`requests/*.request.json` 为无密钥的请求元数据；`*.response.json` 保存实际原始响应；`results.json` 为汇总；`verification.json` 和 `browser_verification.json` 为检查记录。

运行脚本 `run_dedup.py` 通过 `--key-stdin` 或 `DEEPSEEK_API_KEY` 接收凭据，凭据只在内存中使用。已完成的 case 直接读取缓存；遇到未完成的既有日志会停止，避免静默重复调用。后续改变提示词应建立新的版本目录。
