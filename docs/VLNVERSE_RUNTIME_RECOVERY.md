## 第二次修复：模型子进程异常传播

seed 2 / kujiale_0259 在 GPU 3 加载模型时发生 CUDA OOM。agent.log 报告同卡另一进程
占用 39.88 GiB；外层此前只保存 `Model service failed`，因此被归为 unclassified 并阻塞。
这属于运行脚本的容错遗漏，不能把原因完全归咎于共享服务器。

- 模型启动失败保留子进程退出码、阶段、日志路径及最多 64 KiB 的原始日志尾部；
  从原始证据识别 OOM。模型加载超时仍为 900 秒。
- 模型推理和仿真日志分别增量监测 OOM，并在子进程退出后补查最后一段日志，覆盖轮询间隙。
- 仅仿真侧 OOM 将 scene 升级为分卡；模型侧 OOM 按现有资源准入重新排队。
- 在创建 run.json 前失败的 worker，从该次启动日志识别显存准入错误，记录在 launches/。
  不预建空的 run 目录，避免后续新建任务因目录已存在而失败。
- 保留首次失败计数，仍最多追加三次重试；未知程序错误仍阻塞且不计入完成数量。
- 只更新运行层快照及哈希，不改变模型、观测、种子、动作、评分或可视化协议。
