# Crossing Oracle 位置与朝向纠正实验

用户于 2026-11-03 授权先运行 10 个任务。实验回答：StreamVLN 在 crossing 走错分支后，
由外部 Oracle 将机器人移动到附近的正确分支并调整朝向，保留导航 policy 的全部历史，
它是否能继续完成任务。这里不评测自动错误识别或自主返回能力。

## 固定协议

- 当前多次干预输出：`outputs/oracle_crossing/seed2_10_multi_20261103/`。
  旧单次干预试跑保存在 `seed2_10_20261103/`，完成两条后按用户新要求停止。
  两次试跑不混入新组；固定的十条对照已完整完成，新组复用这些对照。
- 从此前 48 条 seed2 crossing 错误归因记录筛选 10 个不同任务，覆盖 8 个 scene。
- seed2、seed3 的错误出口轨迹经地图对照；其他 seed 的失败仅作为结果证据，不冒称同因。
- 按正常失败的 seed 数、seed2/3 出口轨迹的一致性排序，每个 scene 最多两条；运行前固定。
- 两组各 10 次导航：无干预 control、多次纠正 oracle；固定 seed2，原 StreamVLN 权重和 physical 模式。
- Oracle 使用当前 RGB、指令、当前位置、地图和参考路线，实时审阅后写入显式决定。
  这些特权信息只进入仿真侧审阅，不发送给 StreamVLN。
- 检查点接近后，在原动作队列自然执行结束、下一次正常推理之前暂停仿真等待审阅。
  不清空待执行动作，不提前生成新动作，不改变原模型的缓存生命周期。
- 纠正目标：参考路线距离对应 crossing 的最近点，再向前约 0.75 米；朝向沿正确路径。
  冻结目标距地图 crossing 中心约 0.75–1.32 米。所有目标均落于已有静态可通行区域。
- 调整根位置和 yaw；恢复本次初始站立关节姿态、清零速度并更新底层运动控制器，站稳 50 个物理 tick。
  这些 tick 计入任务预算；不调用导航模型、不重置任务、不重置导航 memory、不告知模型发生了纠正。
- 导航历史图像、KV cache、模型输入 embedding cache、步号、动作队列及 reset 次数，
  在瞬移前后以只读内容指纹校验。底层步行控制器与导航 policy 是不同模块。
- “尽早纠正”指确认实际进入错误分支之后尽早接管，并非尚未到 crossing 就预先替模型选路。
  接近首个 crossing 的 2.5 米范围只启动审阅；转头本身不触发瞬移。审阅间隔及原动作队列
  边界仍会带来延迟。地图 crossing 圆心是区域标记，不是必须跨过的精确几何触发线。
- 用户明确允许每条多次纠正。第一次纠正后仍持续审阅，再次走错可继续接管。
  同一路口可以重复纠正，也可以在后续路口纠正；没有一次干预上限。
  每次都从运行前冻结的该任务参考路线落点中显式选择，并记录理由与独立 memory 校验。
  后续停止、跌倒、卡住与物理时间预算沿用原评测规则；终止后不重置任务，不按结果换样本。
- 等待 Oracle 实时审阅是正在进行的任务，没有 10 分钟自动退出规则。
  完成、取消或异常退出后清理本任务的模型和仿真进程，并核验 GPU 释放。

## 启动与实时操作

从项目根目录执行。先查看所有 GPU，使用当前空闲且显存充足的卡；以下编号只是本次实际分配。
不要并行启动占用同一 GPU 的两组。

```bash
python3 -B scripts/run_oracle_crossing.py --arm oracle --gpu 0 --sim-gpu 0
```

入口先核验冻结源码与已有权重，读取两次 GPU 状态，然后启动本组。完成后自动释放。
本次已完成对照使用 GPU 0（模型）和 GPU 3（仿真）；多次干预组启动时 GPU 3 已有他人任务，
因此模型与仿真均使用空闲的 GPU 0。算法、种子和物理配置保持一致，实际分配保存在运行清单。
首次启动可能需要较长的 Isaac 场景/渲染初始化；不进行下载。
已完成组再次执行会保留原结果；入口自动续跑未完成任务。中断重试必须保留尝试记录。

当 `oracle_records/pending.json` 显示 `waiting` 时：

```bash
benchmarks/vlnverse/.venv/bin/python -B scripts/oracle_crossing_console.py show
```

查看生成的 `review.jpg`：左侧为当前 RGB，右侧为地图，下方为已发生的历史画面。
绿线参考路线、蓝线实际路径、红色机器人位置与朝向、紫色纠正目标与朝向。
审阅后使用明确理由回应；每条回应绑定唯一 request ID，旧回应不能用于新请求。

```bash
benchmarks/vlnverse/.venv/bin/python -B scripts/oracle_crossing_console.py respond \
  --decision continue --skip-actions 4 --reason '已检查当前画面和轨迹，仍在接近路口，尚未确认进入错误分支。'

benchmarks/vlnverse/.venv/bin/python -B scripts/oracle_crossing_console.py respond \
  --decision teleport --target C01 --reason '这里必须替换为本条任务实时观察到的具体错误分支及指令证据，C01 也须替换为对应的已审阅落点。'
```

第二条是参数示例，不能不经审阅自动执行。`--decision abort` 会终止当前尝试并触发清理。
终端 Ctrl+C 同样通过父进程清理所属子进程；不要使用广泛匹配的 `pkill`。

## 结果口径

查看 `status_control.json`、`status_oracle.json` 和对应运行目录的 `result.json`、`validation.json`。
Oracle 每个任务保存原始观测、动作、审阅请求/回应、瞬移起终点、前后图像、memory 校验和结束评分。
如果这次没有走错或没有到达干预点，单列未干预；不冒称完成了纠正。

报告成对 SR、NE、对照失败后被救回的任务数、反向变化、纠正次数与多次纠正后的成功比例。
任何一次交接已进入官方成功半径的任务单列；另统计所有交接都在成功半径外的结果。
HTML 分别标出每条瞬移虚线、每次前后画面与 memory 证明，视频叠加累计纠正次数。
带瞬移的 SPL/TL 不是原版 benchmark 的可比成绩；轨迹展示必须将瞬移边单独画为虚线。
这是经错误样本筛选的小规模 Oracle 辅助实验，不代表完整 Val Unseen 的提升。

### 确认走错后尽早纠正组已完成（2026-11-04）

固定十条对照 SR 为 0/10；多次 Oracle 纠正组官方 SR 为 10/10，平均 NE 1.156 米，
没有跌倒或卡住。共 18 次纠正，5 条任务进行了多次纠正；全部 memory 内容指纹一致，
全部落地站稳。六条任务的所有交接均在官方 3 米成功半径外，其中一条包含局部家具
碰撞后的恢复；除去该条后，剩余五条均成功。其余四条包含近目标交接，必须单列。
`kujiale_0123_fix_30_2` 的第二次纠正前已在成功半径内，不能将该次纠正解释为提高 SR。
`kujiale_0036_0_0` 最后停在卧室入口附近，官方 NE 为 0.191 米；官方位置判定成功不等于
已经严格完成了指令中所有语义要求，应结合视频核查。

结果目录中的 `verification_final.json` 保存十条唯一任务核验、18 次 memory 校验、
旧进程退出与 GPU 释放记录及下载包校验和。`report/index.html` 为完整交互报告，
`oracle_crossing_10_review.zip` 包含 HTML、两组视频及 CSV/JSON。
`scripts/report_oracle_comparison.py` 汇总尽早纠正与四组延迟结果，尚未完成的组明确显示状态。

## 后续四组：相同十条，3 / 5 / 8 / 12 米后纠正

用户取消了追加不同任务的计划，随后授权在当前十条结束后运行四组延迟纠正，
阈值明确指定为 3、5、8、12 米。这里的距离是机器人到完整正确参考折线的
最短水平距离，投影到各线段计算；不使用最近离散采样点，不计高度，不按累计路程。

每一步记录观测和距离；未到阈值时正常导航。达到阈值后，在原动作队列自然为空的
下一次推理边界暂停，由实时 Oracle 检查画面、已发生的轨迹与指令，确认错误后
显式选择相关 crossing 的冻结落点。仅距离超过阈值不会自动瞬移。
若阈值在队列中途达到，实际交接可能略晚，保存触发时实际距离。
纠正后继续同样的阈值规则，仍允许多次纠正且保留 memory。

四组复用相同十条对照和相同落点，不扩大样本。若在达阈值前已经按原规则停止、
跌倒、卡住或耗尽预算，保留结束结果并单列未触发；不强迫任务继续以凑够偏移距离。
分别汇总全十条 SR、实际干预数量、纠正次数、未触发数量、最大实际偏移以及每次 memory 校验。

`scripts/prepare_oracle_delays.py` 只准备四组清单与冻结代码，不启动 GPU。
后续输出为 `outputs/oracle_crossing/seed2_10_delay{3,5,8,12}m_20261103/`。
运行入口核验当前尽早纠正组已完成，再允许启动延迟组。例如第一组：

```bash
python3 -B scripts/run_oracle_crossing.py \
  --campaign outputs/oracle_crossing/seed2_10_delay3m_20261103 \
  --arm oracle --gpu 0 --sim-gpu 0
benchmarks/vlnverse/.venv/bin/python -B scripts/oracle_crossing_console.py show \
  --campaign outputs/oracle_crossing/seed2_10_delay3m_20261103
```

每组启动前重新检查 GPU；当前编号仅为示例。当前尽早纠正组使用既有冻结快照，
后续阈值实现的编辑不会改变已在运行的实验。

### 五组最终结果（2026-11-04）

五组各十条均已完成，共 50 次导航；无干预对照复用先前完成的十条（SR 0/10）。
全部 26 次实际纠正均通过 memory 内容指纹及落地稳定性检查。

| 纠正时机 | 全组成功 | 实际干预任务 | 干预任务中的成功 | 纠正次数 | 无干预成功 | 跌倒 |
| --- | --- | --- | --- | --- | --- | --- |
| 确认走错后尽早纠正 | 10/10 | 10 | 10/10 | 18 | 0 | 0 |
| 偏移 3 米 | 5/10 | 6 | 4/6 | 7 | 1 | 1 |
| 偏移 5 米 | 0/10 | 1 | 0/1 | 1 | 0 | 0 |
| 偏移 8 米 | 1/10 | 0 | 不适用 | 0 | 1 | 1 |
| 偏移 12 米 | 1/10 | 0 | 不适用 | 0 | 1 | 0 |

3 米组的 `kujiale_0036_3_2`、8 米组的 `kujiale_0207_60_4`、12 米组的
`kujiale_0240_8_4` 都是在未干预的情况下成功，不能归因于纠正。
8 米和 12 米组所有任务都在达到阈值前结束，因此没有测到这两个距离下的纠正后恢复能力。
5 米组有八条始终未达阈值；另有一条 `kujiale_0207_60_4` 虽然最终超过 5 米，
但此时原动作队列中已有 STOP，未出现新的空队列审阅边界，故保留原 STOP 并单列。

相同 seed 的独立物理导航运行并非逐动作完全相同。已核查首条任务的 3 米与 5 米组，
在首次干预前的共同记录中最大水平位置差约 0.228 米，第 52 个动作开始出现动作差异。
因此，这十条的组间结果不能全部归因于纠正时机，也不代表完整 benchmark 的提升。
尽早组的近目标交接和局部碰撞恢复限制仍按上文单列。

所有组均通过运行入口的十条任务与原生模型动作记录核验；8 米和 12 米组没有重跑尝试。
每组 `verification_final.json` 保存校验结果和进程清理证据。最后两组使用的 GPU 0、3
已释放，模型、仿真及启动进程的退出按 PID 与启动时间核验，未停止他人的任务。

汇总入口为 `outputs/oracle_crossing/comparison_20261103/index.html`，各行可打开该组
完整俯视轨迹、瞬移前后画面、审阅理由、memory 核验及视频。
`outputs/oracle_crossing/oracle_crossing_10_all_distances_20261104.zip` 是五组一起下载的完整包；
解压后打开顶层 `index.html`，保留子目录位置。

### 动态回放 HTML v2

新版单文件入口：`outputs/oracle_crossing/oracle_replay_v2_20261104.html`。
五组与十条任务在同一界面切换，内嵌全部逐步 RGB 预览和高分辨率纠正前后画面，
可直接离线打开，无需视频文件、模型服务或仿真器。

地图支持播放/暂停、拖动时间轴、逐节点查看、速度调节、滚轮缩放和拖动平移。
S 为实际起点，G 为参考目标，E 为实际终点；C 为此前预标定的相关 crossing。
每次纠正的 P/T 分别是精确记录的起点/落点，以紫色虚线箭头连接；回放直接跳变，
不会把瞬移画成行走。当前位置箭头使用实录机身朝向，终止时缺少独立朝向则不画箭头。

D≈ 是偏离区间的回看起点，不是精确的语义错误起始标注。26 次纠正中，10 次依据审阅
文字明确提到的观察区间，16 次按当前行走段最后接近相关 crossing 的位置回溯估计。
这些区间只用于可视化，没有更新原始错误归因或实验成绩。每条的具体依据显示在右侧。
未干预运行的红色段仅作距参考路线 ≥0.5 米的几何提示，须有连续三条观测满足条件；
不据此宣布语义走错。终止节点复用末次观测时，界面明确说明。
